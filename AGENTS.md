`opp` is one Bun/TypeScript CLI that ranks OpenRouter's endpoints for a model and prints the routing that pins the best one. Let code and tests carry the design; keep docs minimal. `README.md` is for people using `opp`, not a design log. No time estimates anywhere.

- `provider-picker.ts` is the whole tool, in `// ----` sections (Policy, Types, Arguments, Eligibility and ranking, Auth and output hygiene, OpenRouter, Rendering, Main); `provider-picker.test.ts` tests it. The ranking thresholds are the constants under Policy; a change to them or to the ranking changes README's "How it picks" and `--help` in the same PR.
- `prompts/` holds standing prompts: `orchestrator.md` for the session that dispatches issues to agents, `docs-audit.md` for the periodic pass that checks every doc against the code.
- Work comes from GitHub issues on `johnrees/openrouter-provider-picker`, in the order `agent-gh next` gives: `ready` marks an issue approved for agents, native blocked-by links say when it is workable, `P0`..`P3` break ties, `model:`/`effort:` say who takes it. New issues follow `.github/ISSUE_TEMPLATE/task.md`. Take one with `agent-gh claim <n>`; run `agent-gh review sweep` before each push; before `gh pr ready`, run `agent-gh review full` and answer each finding with `agent-gh reply`. A PR merges once Codex approves.
- A pull request body opens with `Closes #N.`, then two or three plain sentences a newcomer could follow: what the change does and why it matters, with an example where one helps (`--verify` now fails an endpoint that answers in text when a tool call was required). Then a `---` line, then the detail: changes, tests, live runs (`.github/PULL_REQUEST_TEMPLATE.md`). The claim's draft body is a placeholder; fill the template before `gh pr ready`.
- Checks: `bun install --frozen-lockfile`, `bun test`, `bun check`, `bun fmt --check` (CI and `agent-gh review full` run the same, from `.github/agent-review.json`). Bun-native only: no `tsc`, prettier or other toolchain dependencies; dependencies at their latest versions.
- Tests run against a mocked OpenRouter and never touch the network. Live runs (`--verify` sends paid requests) are evidence for the PR body, not tests. The OpenRouter key is only ever sent to openrouter.ai and never printed, logged or posted.
- Record results and decisions on the issue they answer. When you finish an issue, do what its **When done, update** line says.
